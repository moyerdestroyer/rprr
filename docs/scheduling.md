# Local scheduling

`rprr poll` makes one pass and exits. It uses the authenticated `gh` user and creates a pending review for each open PR with a direct review request, including requests that predate installation. Finish `rprr setup`, verify `rprr doctor --deep`, and run `rprr poll` once manually before scheduling it. Check `rprr drafts` or `rprr status` afterward.

## systemd user timer (Linux)

The CLI generates a service unit for the current `rprr` executable, with the agent and GitHub CLI directories on its path, then validates it. Installing the unit does not start the timer. The first-run setup can enable it when you say so:

```bash
rprr setup
rprr service install
rprr service status
rprr service enable
rprr status
rprr drafts
```

`rprr service disable` stops future runs. `rprr service uninstall` disables the timer and removes only units generated by RPRR. Re-run `rprr service install` if the installed CLI or agent path changes. The generated timer checks every 15 minutes.

The static examples target an install-script binary at `~/.local/bin/rprr`. `rprr service install` writes the command for the copy you are running, including a source checkout. To install the examples yourself:

```bash
test -x "$HOME/.local/bin/rprr"
mkdir -p "$HOME/.config/systemd/user"
cp examples/systemd/rprr.service examples/systemd/rprr.timer "$HOME/.config/systemd/user/"
systemctl --user daemon-reload
systemctl --user enable --now rprr.timer
systemctl --user list-timers rprr.timer
```

The generated service includes the `rprr`, `gh`, and configured agent directories, plus the install-time `PATH`. It carries over XDG directory overrides and `GH_CONFIG_DIR` from the environment used during install. Re-run `rprr service install` after changing your agent installation or `PATH`. RPRR attempts a `notify-send` desktop toast after creating a draft, but user services may not have a desktop notification session. The draft remains in GitHub and in `rprr drafts`. Test the service directly:

```bash
systemctl --user start rprr.service
systemctl --user status rprr.service
journalctl --user -u rprr.service -n 50 --no-pager
rprr status
```

`Persistent=true` triggers a catch-up run when an inactive timer starts after a missed scheduled time. The user manager normally runs while you have a login session; if you need polling while logged out, enable lingering for your account with `loginctl enable-linger "$USER"`. To stop polling:

```bash
systemctl --user disable --now rprr.timer
```

The service is one-shot, so systemd does not launch a second instance of the same service while it is already running. An agent review can take longer than the 15-minute interval; adjust the timer if that is common.

## cron alternative

Use cron if you do not have a systemd user manager. Edit your user crontab with `crontab -e` and add the following, replacing `/home/YOU` with your absolute home path and adding your agent's executable directory to `PATH` if needed:

```crontab
PATH=/home/YOU/.bun/bin:/home/YOU/.local/bin:/usr/local/bin:/usr/bin:/bin
*/15 * * * * /usr/bin/flock -n /home/YOU/.local/state/rprr/poll.lock /home/YOU/.bun/bin/rprr poll >> /home/YOU/.local/state/rprr/poll.log 2>&1
```

`flock` skips a run if the previous one is still active. The state directory is created by `rprr setup`; adjust both paths if you use a custom `XDG_STATE_HOME`. Cron does not catch up missed runs while the machine is off. Inspect the log and `rprr status` after the first scheduled run. Remove the crontab line to stop polling.

References: [systemd timer](https://www.freedesktop.org/software/systemd/man/latest/systemd.timer.html), [systemd service](https://www.freedesktop.org/software/systemd/man/latest/systemd.service.html), [crontab format](https://man7.org/linux/man-pages/man5/crontab.5.html).
